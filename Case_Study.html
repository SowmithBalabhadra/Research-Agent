Where a human was needed

The research pipeline automates the repetitive evidence work; judgment stays explicit. No external autonomous research agent is being claimed.

  • Verification: a human/independent reviewer checks a sample against the cited URLs.
  • Rule improvement: recurring misses are converted into extraction rules and the affected research is rerun.
  • Final judgment: gated, unknown and difficult cases are not silently converted into positive findings.
  • Submission cleanup: a duplicate record must be removed before treating the current 101-record snapshot as the canonical 100-app dataset.

A Python research runner performs source discovery, fetches public documentation, extracts structured facts, and writes JSON results. It is not presented as an external autonomous agent or as making calls to the researched apps themselves.

Verification loop

27 apps were independently sampled and checked against the cited evidence.

  1. Cross-check generated fields against the supplied documentation.
  2. Identify systematic errors, not just isolated misses.
  3. Update extraction rules for recurring failure modes.
  4. Rerun the affected research and regenerate analysis.
Hits: the sample confirmed the core research schema, API availability and many authentication/access claims against the supplied evidence.

Misses: OAuth method/flow mapping, MCP authentication, access/gating specificity, and official-vs-third-party MCP classification were recurring failure modes.

Action: those misses were turned into extraction rules and the affected research was rerun.

What changed

  • OAuth flows now require an OAuth method mapping.
  • MCP auth is separated from normal API auth.
  • Unknown is preserved when evidence does not establish a fact.
  • Official/native MCP is distinguished from third-party servers.
  • Evidence is retained for traceability.
